# OP-APP Project Harness & Agent Guidelines

## 1. Project Overview & Architecture

OP-APP is a Laravel-based internal operations web application designed to manage and synchronize business data two-ways with Google Sheets without requiring complex Google Cloud OAuth setup.

- **Theme & Aesthetics**: Clean Light Blue ("Blue light") enterprise UI with collapsible sidebar, real-time change markers, and glassmorphic modal forms.
- **Tech Stack**: PHP 8.5+, Laravel v13.38.0, SQLite (Testing) / MySQL (Production), Tailwind CSS, Alpine.js / Vanilla JS, Blade templates.
- **Test & Lint Suite**: Pest (`vendor/bin/pest`), Laravel Pint (`vendor/bin/pint --dirty --format agent`), Vite (`npm run build`).

## 3. Two-Way Google Sheets Synchronization Engine

Located in `app/Services/GoogleSheetService.php`.

### A. Sync Workflows
1. **Pull (Google Sheet → Local Database)**:
   - Reads rows via public CSV export URL or Apps Script GET endpoint.
   - Maps row columns to model attributes via `fromSheetRow($row)`.
   - Deduplicates and updates existing records by `code` or `tax_id`.
2. **Push Marked Changes (`push_marked`)**:
   - Only pushes modified records: creates (`pending_create`), updates (`pending_update`), and deletes (`PendingSheetSync` with status `pending`).
   - Sends payload `action: 'sync_changes'` to the Google Apps Script Webhook.
   - On success, updates local statuses to `'synced'` and clears pending markers.
3. **Push All (`push_all`)**:
   - Overwrites entire sheet with local records via `action: 'sync_all'`.

### B. Dynamic Primary Key Column
- Each `GoogleSheetConfig` has a `primary_key_column` field (default: `'A'`).
- `getKeyColumnIndex()` converts column letters (`'A'` → 0, `'B'` → 1, `'C'` → 2, `'AA'` → 26) to 0-based column indices.
- Both `keyColumn` (letter) and `keyColumnIndex` (integer) are sent to Apps Script to identify unique records.

### C. Google Apps Script Webhook Connector (v2.1)
- Template generated by `GoogleSheetService::getGoogleAppsScriptTemplate()`.
- Supported actions: `sync_changes`, `append`, `update`, `delete`, `sync_all`, `doGet`.
- **Bottom-up multi-row deletion**: Always deletes matching rows from bottom to top (`for (var i = currentData.length - 1; i >= 1; i--)`) to eliminate all duplicate rows of a code without shifting indices.
- **CRITICAL DEPLOYMENT GOTCHA**: When updating `Code.gs` in Google Sheets, clicking "Save" only saves drafts! You **MUST** select:
  `Triển khai (Deploy) > Quản lý bản triển khai (Manage deployments) > Chỉnh sửa ✏️ > Phiên bản (Version): "Phiên bản mới" (New version) > Triển khai`.
  Otherwise, Google continues serving the old script version!

## 4. Development, Testing & Verification Guidelines

### A. Testing Rules
- Framework: **Pest**. Run tests with `vendor/bin/pest` or `php artisan test --compact`.
- Narrow test runs: `vendor/bin/pest --filter=test_name` or `vendor/bin/pest tests/Feature/GoogleSheetTest.php`.
- Test database: Uses in-memory SQLite (`:memory:`) in `phpunit.xml`.
- When creating models in tests, always use factories (`Model::factory()->create()`).
- Do NOT delete existing tests without explicit user request.

### B. Code Style & Linting
- Formatter: **Laravel Pint**. Run `vendor/bin/pint --dirty --format agent` before finalizing any PHP edits.
- PHP 8.5 standards:
  - Explicit return types and parameter types on all functions/methods.
  - Constructor property promotion for dependencies.
  - Strict curly braces for all control blocks.

### C. Controller Best Practices
- Never assume external sync succeeds. Always check `$result['success'] ?? false`:
  - If failed: Redirect with `->with('error', $result['message'])`.
  - If succeeded: Redirect with `->with('success', $result['message'])`.
  - JSON responses must return HTTP 200 on success or HTTP 422 on failure.

### D. Frontend & Assets
- If view changes don't appear or Vite manifest errors occur, run `npm run build`.
- Blade views reside in `resources/views/{customers, suppliers, products, sheets, layouts}/`.
